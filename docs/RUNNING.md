# Запуск и техническая справка

Все команды выполняются из корня showcase-репозитория. Данные синтетические; состояние существует только в памяти.

## Попробовать за несколько минут

Python **3.11+**. Все команды ниже выполняются из корня этого showcase-репозитория.

```sh
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python demo.py
python demo.py --scenario proactive --approve-demo
python demo.py --interactive
```

`demo.py` выполняет сценарий в одном процессе без серверов, ключей и сетевых
запросов. `--approve-demo` явно подтверждает только синтетические действия.
Интерактивный режим позволяет читать письма, принимать события и по отдельности
подтверждать или отклонять предложения. При выходе состояние теряется.

`constraints.txt` фиксирует версии проверенного окружения. Обновлять их следует
вместе с повторным запуском тестов.

Для ручного исследования HTTP API:

```sh
python -m server
```

Откройте [Swagger](http://127.0.0.1:8765/docs):

1. `POST /demo/connect` с `{}` подключает демо-сессию `alice`.
2. `POST /tools/mail/search` с `{"query":{},"page_size":5}` возвращает ResultSet.
3. `POST /tools/mail/read`: передайте `result_set_id`, выбранные `refs` и
   `detail: "preview"` либо `"full"`.
4. `POST /demo/events/mail-received` с `{"event_key":"arrival-1"}` создаёт
   письмо и два предложения действий. В ответе будут их идентификаторы.
5. `POST /demo/actions/{action_id}/decision` с `{"approve":true}` имитирует действие.
6. `GET /demo/state` показывает synthetic outbox, черновики, папки и задачи CRM.

Интерфейс Swagger может загружать JS/CSS с CDN. CLI и backend не требуют сети
после установки зависимостей. Сервер привязан к `127.0.0.1:8765`.

## Что можно проверить

| Возможность | Где потрогать |
|---|---|
| Поиск по людям, организациям, группам и датам | `/tools/mail/search`; в демо — точное совпадение имени или email |
| Пагинация сохранённого результата | повторный search с `result_set_id` и `cursor` |
| Preview, full, вложения, усечение текста | `/tools/mail/read`; сообщения m1 и m3 |
| Неизвестный/слишком большой размер | m4 и m5: контент не извлекается |
| Короткие handles и компактный текст для модели | `/portal/tools/mail/search` и `/portal/tools/mail/read` |
| Observation-only аннотации | фиксированная synthetic метка, не влияет на выборку |
| Раздельные демо-сессии, срок жизни, смена поколения | заголовок `X-Demo-Session`: alice/bob; `/demo/fault` |
| Отказ провайдера, неполная выборка, занятость | `/demo/fault`, тесты поведения |
| Подключение, отмена, отказ | `/demo/connect`; никакие пароли не принимаются |
| Реальные карточки прогресса | `/demo/progress` после подключения |
| Черновик, отправка, ответ, пересылка, прочитано, перемещение | `/tools/actions/propose` → ручное решение |
| Получение нового письма и проактивное предложение | `/demo/events/mail-received` |
| Bitrix24: контакт и задача | `/tools/bitrix/contact`, действие `bitrix_task` |
| Повтор событий, отклонение, ошибка CRM и повтор | повтор event_key; `/demo/fault`; тесты |

Удаление сообщений не предусмотрено ни контрактом действий, ни коннектором.
Перемещение ограничено synthetic папками `Archive` и `Processed`.

## Тесты и упаковка

```sh
python -m pip install -r requirements-dev.txt
python -m pytest
python tools/release.py --check
python tools/release.py --build
```

Архив создаётся в `dist/mail-agent-showcase.zip` **по явному списку**
`public-files.json`; туда не попадают родительский проект, окружение, заметки,
базы и runtime-файлы. Проверка сверяет состав, импорты и происхождение исходников.
Это воспроизводимая техническая проверка выбранного состава, не математическое
доказательство отсутствия любого возможного секрета.

## Границы демонстрации

Реальные IMAP/SMTP, MIME parser, identity matching/ranking, encrypted SQLite,
production onboarding, durable jobs, deployment и рабочий системный промпт
не распространяются. In-memory ResultSets и подтверждения — упрощённые реализации.
`alice`/`bob` выбираются посетителем и **не являются аутентификацией**. Сервер
предназначен для локального изучения одним пользователем, не для общего доступа.

Данные каждого письма считаются недоверенными. Маркеры в выдаче показывают эту
границу, но сами по себе не обеспечивают защиту от prompt injection. Здесь нет
LLM, выполняющей инструкции из письма.

OpenWebUI-адаптер в `openwebui_tools/mail_agent_demo.py` можно импортировать отдельно
при запуске OpenWebUI на том же хосте. Сначала подключите alice в Swagger.
Адаптер предлагает действия, но не предоставляет модели инструмент подтверждения.
Для Docker/удалённого портала сетевую интеграцию нужно проектировать отдельно.

Этот репозиторий демонстрирует архитектуру и выбранную реализацию; показ
синтетической интеграции не означает проверку соответствующей промышленной системы.
Условия публикации материалов изложены в [NOTICE.md](../NOTICE.md).
